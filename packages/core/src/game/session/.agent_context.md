Active game-session domain.

Cross-module calls use module namespaces (`Ballot.tallyVotes`, `Log.appendGameLog`); same-file helpers stay unqualified.

- `index.ts`: `Game.Session` facade; exposes `Read`, `Targets`, `Ballot`, `Phase`, `Events`, `Chat`, `Loop`, `Log`, and `Schema`.
- `read.ts`: full session reads, active-player lookup, and sync payload projection.
- `targets.ts`: player target submission.
- `engine.ts`: engine actor reconstruction from persisted actors and player targets.
- `chat.ts`: server-side game chat audit recording.
- `chat.policy.ts`: pure chat send/subscription policy helpers shared by backend and frontend; both form `Game.Session.Chat` server facade.
- `loop.ts`: Step Functions execution ARN storage.
- `ballot.ts`: vote/verdict commands, pure tally rules, and internal ballot reset helpers.
- `assert.ts`: shared command-validity assertions that throw stable input errors.
- `player-state.ts`: internal on-trial and target reset helpers.
- `phase-transition.ts`: idempotent loop-command result schema and persistence.
- `phase.ts`: authoritative, row-locked/idempotent phase-advance loop and transition helpers.
- `events.ts`: server-only realtime events; future EventBus events belong here.
- `log.ts`: server-only game/engine audit contracts and transactional append helpers.
- `schema.ts`: canonical pure `GameErrors`/`GameSessionErrors`, game/session info, phase, player, sync, topic, and engine contracts.

No session table exists: `Game.Session` organizes active-match behavior around existing game tables.
