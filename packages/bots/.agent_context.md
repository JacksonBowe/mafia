# packages/bots

Local bot control panel + headless runner. Bots authenticate and connect to the
API + realtime exactly like a real user. Panel lists open lobbies, can fill a
selected lobby with bots, connect/disconnect, leave/start, refresh, and inspect
bot status/logs.

## Files

| Path                | Purpose                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| `src/index.ts`      | Headless CLI entry. Parses `--lobby-id`/`--count`/`--keys`, reads SST `Resource`, spawns bots. |
| `src/panel.ts`      | OpenTUI control panel (`bun run panel`; optional `--lobby-id` preselects).                     |
| `src/manager.ts`    | Multi-bot manager for panel commands, fill-lobby behavior, and snapshots.                      |
| `src/session.ts`    | `BotSession` lifecycle: auth, realtime, dynamic lobby/game actions, logs.                      |
| `src/types.ts`      | Shared bot status/snapshot/log/config types.                                                   |
| `src/bot.ts`        | `runBot()` wrapper for old headless behavior.                                                  |
| `src/realtime.ts`   | `BotRealtime` MQTT client (mirrors web store; static API key => mqtt auto-reconnect).          |
| `src/config.ts`     | Loads + zod-validates `bots.local.json` (raw API keys, git-ignored).                           |
| `bots.example.json` | Template for `bots.local.json`.                                                                |

## Auth

Bots send their raw key as the `x-api-key` header (REST) and as the MQTT
password (realtime). The backend resolves it via `User.ApiKey.getUserForKey`.
Only key hashes are stored in the DB (`user_api_key` table).

## Run

```bash
cp bots.example.json bots.local.json   # fill in raw keys matching DB rows
bunx sst shell -- bun run src/index.ts --lobby-id <lobbyId> --count 2
bun --cwd packages/bots run panel
```

Panel shortcuts are shown in-app. Click lobby/bot rows to select; `R` refreshes
lobbies and `f` fills the selected lobby up to `MAX_PLAYERS`.

## Notes

- Wire realtime payload is `{ type, properties }`; `type` has NO `realtime.`
  prefix (the web bus adds that client-side). Match e.g. `'lobby.started'`.
- Topic namespace comes from `topicPrefix()` (`@mafia/core/realtime`).
