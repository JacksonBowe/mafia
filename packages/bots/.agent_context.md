# packages/bots

Backend "target dummy" bots. They authenticate and connect to the API +
realtime exactly like a real user, but take no game actions yet (listen/log
only). First-pass plumbing for programmatic players.

## Files

| Path              | Purpose                                                              |
| ----------------- | ------------------------------------------------------------------- |
| `src/index.ts`    | CLI entry. Parses `--lobby-id`/`--count`/`--keys`, reads SST `Resource`, spawns bots. |
| `src/bot.ts`      | `runBot()` — SDK client + realtime; joins lobby, subscribes on `lobby.started`. |
| `src/realtime.ts` | `BotRealtime` MQTT client (mirrors web store; static API key => mqtt auto-reconnect). |
| `src/config.ts`   | Loads + zod-validates `bots.local.json` (raw API keys, git-ignored). |
| `bots.example.json` | Template for `bots.local.json`.                                   |

## Auth

Bots send their raw key as the `x-api-key` header (REST) and as the MQTT
password (realtime). The backend resolves it via `User.ApiKey.getUserForKey`.
Only key hashes are stored in the DB (`user_api_key` table).

## Run

```bash
cp bots.example.json bots.local.json   # fill in raw keys matching DB rows
bunx sst shell -- bun run src/index.ts --lobby-id <lobbyId> --count 2
```

## Notes

- Wire realtime payload is `{ type, properties }`; `type` has NO `realtime.`
  prefix (the web bus adds that client-side). Match e.g. `'lobby.started'`.
- Topic namespace comes from `topicPrefix()` (`@mafia/core/realtime`).
